# Cluster pipeline: DMAVAE / CMAVAE / LSEM / LSEM-I / DML simulation

## Layout (on the cluster, `$HOME/dmavae_sim/`)

```
dmavae_sim/
├── R/
│   ├── scenarios.R           # scenario grid + task_id → (scenario, rep) mapping
│   ├── shared_dgp_linear.R   # your DGP (unchanged)
│   ├── generate_data.R       # one-rep data generator
│   ├── rep_io.R              # CSV read/write helpers
│   ├── run_lsem.R
│   ├── run_lsem_i.R
│   └── run_dml.R
├── py/
│   ├── scenarios.py          # Python mirror of scenarios.R
│   ├── load_datasets.py      # reads CSVs the R generator wrote
│   ├── dmavae_gpu.py         # your file (unchanged)
│   ├── cmavae_gpu.py         # your file (unchanged)
│   ├── run_dmavae.py         # one-rep DMAVAE runner
│   ├── run_cmavae.py         # one-rep CMAVAE runner
│   └── aggregate_results.py  # combines all per-rep CSVs
├── slurm/
│   ├── gen_data.sbatch
│   ├── run_lsem.sbatch
│   ├── run_lsem_i.sbatch
│   ├── run_dml.sbatch
│   ├── run_dmavae.sbatch
│   ├── run_cmavae.sbatch
│   ├── aggregate.sbatch
│   └── run_all.sh
├── input/                    # generated by gen_data step
├── performance_lsem/         # one folder per method (per-rep result rows)
├── performance_lsem_oracle/
├── performance_lsem_i/
├── performance_lsem_i_oracle/
├── performance_dml/
├── performance_dml_oracle/
├── performance_dmavae/
├── performance_cmavae/
└── logs/                     # slurm logs
```

## Scenarios

8 combinations: `N ∈ {1000, 4000}` × `n_X ∈ {10, 200}` × `sigma2_x ∈ {1, 3}`,
100 replications each → **800 array tasks per stage**.

Each array task does ONE replication. Mapping (identical in R and Python):

```
scenario_id = ((task_id - 1) %/% 100) + 1   # 1..8
rep         = ((task_id - 1) %%  100) + 1   # 1..100
```

The seed for `(scenario_id, rep)` is `1000 * scenario_id + rep`, so the
data is **identical across methods** for fair comparison.

## Setup (one-time)

1. Copy this folder to the cluster:
   ```bash
   scp -r dmavae_sim/ tu_zxojs39@<cluster-login>:/home/tu/tu_tu/tu_zxojs39/
   ```

2. Make sure your `myenv` conda environment has the Python deps:
   ```
   torch  pyro-ppl  numpy  pandas  matplotlib
   ```
   And the R env has `causalweight` (for DML).

3. On the cluster:
   ```bash
   cd $HOME/dmavae_sim
   chmod +x slurm/run_all.sh
   mkdir -p logs
   ```

## Running

### Full pipeline (recommended)

```bash
cd $HOME/dmavae_sim
bash slurm/run_all.sh
```

This submits, in order with SLURM dependencies:

1. `gen_data.sbatch`  (800 tasks, ~15 min/task wallclock cap)
2. All five method arrays (each 800 tasks), each waiting for gen_data
3. `aggregate.sbatch`, waiting for all methods to finish

### Step-by-step (manual)

```bash
sbatch slurm/gen_data.sbatch                              # 1. data
sbatch --dependency=afterok:<gen_jobid> slurm/run_lsem.sbatch
sbatch --dependency=afterok:<gen_jobid> slurm/run_lsem_i.sbatch
sbatch --dependency=afterok:<gen_jobid> slurm/run_dml.sbatch
sbatch --dependency=afterok:<gen_jobid> slurm/run_dmavae.sbatch
sbatch --dependency=afterok:<gen_jobid> slurm/run_cmavae.sbatch
sbatch --dependency=afterany:<j1>:<j2>:<j3>:<j4>:<j5> slurm/aggregate.sbatch
```

### Re-running one method (data already generated)

```bash
bash slurm/run_all.sh skip_gen only dmavae
```

### Re-running a single task (debug)

```bash
cd $HOME/dmavae_sim
PROJECT_ROOT=$HOME/dmavae_sim Rscript R/generate_data.R 1
PROJECT_ROOT=$HOME/dmavae_sim Rscript R/run_lsem.R 1
PROJECT_ROOT=$HOME/dmavae_sim python  py/run_dmavae.py 1
```

## Outputs

Per replication, each method writes one CSV row to:

```
performance_<method>/<scenario_name>/rep<NNN>.csv
```

After running `aggregate.sbatch` (or `python py/aggregate_results.py`):

```
performance_<method>/all_results.csv          # all 800 rows for the method
performance_<method>/summary_by_scenario.csv  # 8 rows, one per scenario
summary_all_methods.csv                       # 40 rows (5 methods x 8 scenarios)
                                              # — counting only proxy versions
```

The summary contains, per (method, scenario):
- `n_reps`, `n_converged` (where relevant)
- mean / sd / RMSE of each bias column (ATE, NDE, NIE)

## Notes / gotchas

- **Resource budgets** (per task):
  - LSEM / LSEM-I:  10 min, 2 GB — overkill but cheap.
  - DML:            1 h, 4 GB — cross-fitting w/ ML learners can be slow at n_X=200, N=4000.
    If you see timeouts in `logs/dml_*.err`, bump `--time` in `slurm/run_dml.sbatch`.
  - DMAVAE/CMAVAE:  2h30, 4 GB, 2 CPUs — 700 epochs at N=4000 on CPU.
    If you see timeouts in `logs/dmavae_*.err`, either:
      (a) bump `--time` to 04:00:00,
      (b) reduce `NUM_EPOCHS` at the top of the python runner,
      (c) request a GPU partition (see comment in the sbatch).
- **DML errors** in some replications are caught and written as NA rows — the
  aggregator skips them in the mean/sd but counts them in `n_reps`.
- **Total tasks**: 800 (gen) + 5 × 800 (methods) + 1 (aggregate) = 4801 array tasks.
  bwUniCluster's QoS limits how many run concurrently; the scheduler queues the rest.
